## 1. 테스트 환경

| 구분 | 내용 |
|---|---|
| 보드 | NUCLEO-F103RB + NUCLEO EVB v2 |
| 통신 | HM-10 (BLE) ↔ USART1 9600 bps, 스마트폰 앱 |
| 로그 | USART2 115200 bps → ST-LINK 가상 COM → Tera Term |
| 계측기 | 디지털 멀티미터, CubeIDE 디버거(SFR) |
| 앱 | NUCLEO EVBDemo BLE (교재 제공 Android 앱) |

## 2. 계산값 (설정으로 정해지는 값)

| 항목 | 계산값 | 근거 |
|---|---|---|
| R 패킷 간격 | 50 ms (TIM2 1 ms × 50) | [계산] `MX_TIM2_Init`, `HAL_TIM_PeriodElapsedCallback` |
| 장치 1개 갱신 주기 | 350 ms (7개 순환) | [계산] |
| R 패킷 전송 시간 | 7바이트 7.3 ms ~ 10바이트 10.4 ms | [계산] 9600 bps, 1바이트 10비트 |
| ADC 3채널 1회 | 94.5 µs | [계산] (239.5 + 12.5) / 8 MHz × 3 |
| 서보 PWM | 50 Hz, 펄스 550~2360 µs | [계산] TIM4 1 MHz / 20000 |
| RGB PWM | 약 1.96 kHz, 256단계 | [계산] TIM3 center-aligned |
| SPI2 | 1 MHz, Mode 1 | [계산] 32 MHz / 32 |
| I2C1 | 400 kHz | [계산] |
| HDC1080 변환 | 12.85 ms (온도 6.35 + 습도 6.50) | HDC1080 데이터시트 p.5 |

**레지스터 확인 [예정]:** 디버거 SFR 뷰로 `TIM4->CCER`(CC2P = 1, 극성 LOW), `TIM3->CR1`(CMS = 11), `SPI2->CR1`(CPHA = 1, BR = ÷32), `USART1->BRR`, `ADC1->SQR3` / `SMPR2`, `DMA1_Channel1->CCR`(CIRC = 1)를 캡처하면 설정이 하드웨어에 들어간 것을 증명할 수 있습니다.

## 3. 실측 계획

| 항목 | 방법 | 기대값 |
|---|---|---|
| E5V 전압 | EVB의 E5V–GND를 멀티미터로 | 약 5 V |
| DAC 출력 | 앱에서 2048 전송 → P1 단자(TP1–TP2) 전압 | E5V ÷ 2 |
| DAC 출력 | 4095 전송 | 약 E5V |
| 엔코더 | 돌리기·누르기 영상 (앱 R 화면과 함께) | 카운트 증감, 누르면 0 |
| HDC1080 히터 영향 | 히터를 끈 뒤(05 이슈 9) 같은 시점의 TC1047·HDC1080 온도 비교 | 차이가 줄면 히터 영향 |
| HDC1080 풀업 | 전원 끄고 모듈 SCL–3V3 저항 | 수 kΩ (없으면 개방) |

## 5. 한계

1. 메인 루프가 패킷을 해석하는 동안 들어온 패킷은 버립니다. 앱에서 값을 연속으로 바꾸면 중간 값 일부를 건너뛸 수 있습니다 (마지막 값은 반영, [05 문서](05_troubleshooting.md) 1-2절). 모두 살리려면 더블 버퍼·링버퍼가 필요합니다.
2. 체크섬이 없어 통신 오류를 검출하지 못합니다.
3. 메인 루프가 HDC1080 측정(15 ms)마다 멈춰 W 패킷 처리가 늦어질 수 있습니다.
4. 센서 절대값(온도·조도)은 기준 장비와 비교하지 않았습니다.

## 6. 재현 방법

1. NUCLEO-F103RB를 EVB 보드에 체결, HM-10 헤더 P12 연결
2. STM32CubeIDE에서 프로젝트를 열고 Debug 구성으로 빌드 → 다운로드
3. Tera Term: ST-LINK 가상 COM 포트, 115200 bps 8N1 → 부팅 시 `88-2.EVB_DEMO2_RW` 출력 확인
4. 스마트폰 앱에서 HM-10에 연결 → R 값 갱신 확인 → W 명령 전송 후 Tera Term에 `STX_OK` ~ `ETX_OK` 확인
